# SPEC-004 — Markdown report and CLI surface

**Status:** draft — round 1 review (brief-005)
**Author:** ZCode (coordinator)
**Date:** 2026-10-02
**Depends on:** SPEC-003 (plan.v1), fixture corpus (merged — normative)

## 1. Purpose

Define the human-readable report (`report.md`) rendered deterministically from a canonical `plan.json`, and pin the final V0 CLI surface. The JSON plan is machine truth; the report is what a human reads to decide merges (SPEC-000 §2.5: "readable without training").

## 2. CLI surface (V0 final)

- `ua plan <fixture-dir>` — canonical `plan.json` to stdout (existing)
- `ua report <fixture-dir>` — canonical `report.md` to stdout (this spec)
- `ua selftest [fixtures-root]` — corpus: plan bytes, report bytes, permutation, rejection (existing, extended)

## 3. Report contract

Deterministic pure function of the plan: same plan bytes ⇒ same report bytes (LF, trailing newline, UTF-8). Structure:

1. **Title:** `# Impact plan: {packageName} {oldVersion} → {newVersion}` (arrow is the literal `→`).
2. **Summary:** bullet list — delta line (`- Delta: {packageName} {changeType} {oldVersion} → {newVersion} ({ecosystem})`), repos line (`- Repositories: {n-affected} affected · {n-not-affected} not-affected · {n-unknown} unknown`), waves line (`- Waves: {count}{detail}` where detail breaks down ready/conditional/provisional when count > 0, else `- Waves: none (plan stopped: {stop.reason})` plus an indented detail line).
3. **Waves** (`## Waves`): per wave `### Wave {index} — {status}` (status plus ` · blocked on {blockedOn}` when provisional). **Wave-level gates come FIRST, as top-level bullets so GFM attaches them to the wave, never to a unit:** `- Prerequisites: none` or `- Prerequisites:` with nested `  - {p}` items (template order); `- Condition: {c}` when present. Then per unit: `- **{repo}**{package-list} · {basis}` where package-list is ` (publishes {p1}, {p2})` when non-empty (natural order) and basis is the release-unit basis; unit notes as `  - note: {note}` lines; THEN the publication status map as `  - publication: {P}={status}` lines (natural order).
4. **Repositories** (`## Repositories`): GitHub-flavored table `| Repo | Classification | Ownership | Action | Evidence | Confidence | Why |` with one row per repo (plan order); Evidence = evidenceKinds joined `, `; Confidence = `{rung} ×{corroboration}`; Why = reasons joined with `; ` (single line). All cells pass through `Cell()`.
5. **Escaping (all dynamic text):** renderer constants own every heading and bullet marker — dynamic text can never forge structure. Table cells pass through `Cell()`: `\` → `\`, `|` → `\|`, CR/LF → single space. Bullet/line text passes through `Text()`: CR/LF → single space. Render output is normalized LF-only at exit.
6. **Uncertainty** (`## Uncertainty`): `### Contradictions` (when any): per contradiction `- {id} ({subject}): claims by {r1} ({pkg1}), {r2} ({pkg2}); downstream provisional: {list|none}` (claim package IDs included — nothing dropped). `### Gaps` (when any): `- **{subject}**: {detail}`. When both empty: `## Uncertainty` section is `None.` on the following line.

## 4. Acceptance criteria

1. `ua report` output is byte-identical to `golden/report.md` for every fixture that has one.
2. Determinism: report is a pure function of plan bytes — permutation-stable by construction (the selftest proves it via the corpus).
3. Every plan fact appears in the report: all repos, all waves/units/packages/notes/prereqs/conditions, stop detail + cycle path, contradictions, gaps. Nothing invented; nothing dropped.
4. Readable without training (F1 review check by Joe).

## 5. Golden authorship (fidelity note)

F1's `golden/report.md` is hand-authored from these rules. The remaining fixtures' report goldens are generated by the renderer and **explicitly flagged for quorum review in the PR** — the renderer's contract is "deterministic function of already-reviewed plan goldens," so the review verifies the F1 exemplar + rules, then the generated set against those rules.

## 6. Out of scope

Coloring/emoji/sorting options; markdown flavors beyond GFM tables; rendering from non-canonical plans.
